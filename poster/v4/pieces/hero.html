How it works: one proof, and a tree reduction loses all four clamps

The loop (reduce_tree)

@workgroup_size(256) var<workgroup> s: array<u32, 256>; for (var stride = 128u; stride > 0u; stride = stride >> 1u) { if (lid < stride) { s[lid] = s[lid] + s[lid + stride]; } workgroupBarrier(); }

What the analysis derives

  1. 1lid ∈ [0, 255]: the workgroup size
  2. 2stride ∈ [1, 128]: its only update is >> 1
  3. 3lid < stride ⇒ lid ∈ [0, 127]
  4. 4lid + stride ∈ [1, 255] fits s, so no clamp is needed

Emitted SPIR-V (Restrict)

UMin %lid %uint_255 UMin %lid %uint_255 UMin %lid_plus_stride %uint_255 UMin %lid %uint_255
4 → 0 clamps. The binary is byte-identical (sha256) to the build with all checks off.
