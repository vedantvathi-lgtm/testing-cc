   <h5 class="heading settled" data-level="15.2.10.4" id="uniformity-example4"><span class="secno">15.2.10.4. </span><span class="content">Uniformity in a Loop</span><a class="self-link" href="#uniformity-example4"></a></h5>
   <p>In this example, there is an invalid <code>workgroupBarrier</code> function call in a
loop.
The non-uniform built-in value <code>local_invocation_index</code> is the ultimate cause
despite the fact that it appears after the barrier in the loop.
This occurs, because on later iterations some of the invocations in the
workgroup will have exited the loop prematurely while others attempt to execute
the barrier.
The analysis models the inter-iteration dependencies as an edge, where the control
at the start of the loop body (CF_loop_body) depends on the control flow at the
end of the loop body (CF_after_if).</p>

   <p>When invocations in the same subgroup execute different control flow paths, we
say subgroup execution has diverged.
This is a special case of <a data-link-type="dfn" href="#uniform-control-flow" id="ref-for-uniform-control-flow①③">non-uniform control flow</a>.
Divergence affects the semantics of subgroup operations.
The invocations in a subgroup that concurrently execute a subgroup operation
are <dfn class="dfn-paneled" data-dfn-for="subgroups" data-dfn-type="dfn" data-noexport id="subgroups-active">active</dfn> for that operation.
Other invocations in the subgroup are <dfn class="dfn-paneled" data-dfn-for="subgroups" data-dfn-type="dfn" data-noexport id="subgroups-inactive">inactive</dfn>
for that operation.
When the subgroup size exceeds the number of invocations in a subgroup, the
extra hypothetical invocations are considered inactive.
<a data-link-type="dfn" href="#helper-invocation" id="ref-for-helper-invocation③">Helper invocations</a> may be active or inactive in an operation.
That is, on some devices helper invocations may participate in subgroup operations,
while on other devices they may not.</p>
   <p class="note" role="note"><span class="marker">Note:</span> There is considerable non-portability among underlying devices when
operating in non-uniform control flow, and device compilers often aggressively
optimize such code.
The result is that the subgroup may contain a different set of active
invocations than the shader author expects.</p>
